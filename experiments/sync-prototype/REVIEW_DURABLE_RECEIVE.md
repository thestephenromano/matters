# Durable receive review remediation

Reviewed source: PR #107 at merge `ba8f955`.
The active [execution evidence](evidence/record-contract-2026-11-18.json) binds the corrected source, tests and contract. The governing contract is [SYNC_DURABLE_RECEIVE.md](../../docs/SYNC_DURABLE_RECEIVE.md).

## Findings, owning boundaries and corrections

1. **Cross-writer record-ID reuse froze an honest writer.** Record IDs travel in cleartext, and a same-ID/different-bytes pair froze both incarnations. When the colliding records come from different incarnations, nothing shows which writer (or the relay) is at fault. The invariant is that a chain freezes only on evidence that its own signer equivocated. The inbox now freezes an incarnation only when it signs two different successors of one predecessor, or two different records under one record ID. A cross-writer collision freezes neither chain: each record is judged on its own chain and both rows carry `record_id_conflict`. A "first delivery wins" rule was rejected because it makes receivers diverge when deliveries arrive in different orders. The record contract derives each content key from the full header (author and incarnation included), so a cross-writer collision never reuses an AES-GCM key.
2. **Order-dependent domain rejection.** `stage()` judged domain validity on the document holding every record applied so far, so delivery order decided which concurrent record was rejected. The invariant is that a verdict is a function of the record and its causal past alone. Validity is now judged on `fork_at` the record's last operation. If individually valid records merge into a state with no valid projection, `merge_conflict()` reports `domain-merge-conflict` and `projection()` errors. Every receiver holding the same accepted set reaches that same outcome. A deterministic domain merge policy remains an open gate in [SYNC_DESIGN.md](../../docs/SYNC_DESIGN.md).
3. **Wrong same-epoch key recorded as a verdict on input.** The key-distribution format commits to the recipient's KEM key (`key_fp`), not to the epoch content key. A wrong content key for the right epoch therefore cannot be told apart from a bad record, so the receiver must not record a verdict on the input. AEAD failure is now `undecryptable` and is retried on every pass; descendants report `blocked-by-undecryptable-predecessor`. Once history has been accepted, a key that cannot open the latest accepted record is an operational error and nothing commits. A content-key commitment in signed shared state is listed as a remaining gate; it changes the key-distribution format.
4. **Duplicate detection against the latest claim.** Duplicates were compared with the most recent record-ID entry, so in an A/B/A delivery the third copy became a new conflict and candidate. Exact duplicates are now detected by full-record digest. Each one names its first copy (`duplicate-of:<sequence>`), and that copy's classification governs.
5. **Whole-document copies per attempt.** Accepted records were replayed through staging on every call, and every waiting or rejected candidate was staged again on each fixed-point pass. Missing actor counters and declared dependencies are now checked from blob metadata before any copy. Each eligible candidate is staged once per pass with `LoroDoc::fork`, as `Replica` already does. Payload rejections are settled within the call and across calls; they are final because they depend only on the record and its causal past.
6. **Repeated verification of settled history.** Authentication facts depend only on the retained bytes and the bound configuration. They are derived once and committed with the row's classification. The engine snapshot commits in the same transaction as application ordinals and projection, so accepted records are never replayed. A pass with nothing pending performs no signature checks, decryption or staging. A test pins these counts.
7. **Foreign database check counted only tables.** A view-only database was treated as empty and initialized. `matters_sync_prototype::has_user_schema` counts every user schema object (table, index, view, trigger), using case-sensitive `NOT GLOB 'sqlite_*'`. The inbox, the outbox and the sibling `Replica` all use it, and view-only regressions cover all three.
8. **Replacement writer starts accepted at open.** A replacement moves the lineage head, so valid history under the original incarnation authenticated as stale. `Config::authority` now refuses any writer start that names a predecessor, before any storage is created.
9. **First-record helper error precedence.** `open_first_data` again rejects chained records structurally, before context, writer or ML-DSA work.
10. **Duplicated key checks and error helpers.** `authenticate_data` calls `check_epoch_key` instead of repeating it. The inbox and outbox use the library's single `invalid` constructor.

## Regression and mutation evidence

Nine regression tests were written first and run against the reviewed implementation. Each failed for the reported behavior: cross-writer ID reuse, order-dependent verdicts, wrong same-epoch key, A/B/A duplicates, view-only databases for the inbox, outbox and `Replica`, replacement writer starts, and first-record precedence. A tenth, same-writer record-ID equivocation, passed before and after, as a preservation check. The work-budget test needs the new instrumentation, so it has no before-run.

Ten manual mutations were compiled and caught by named tests: judge domain validity on the merged document; skip the causal-past domain check; freeze both writers on cross-writer ID reuse; quarantine on decryption failure; compare duplicates against the latest ID claim; retry earlier payload rejections; stage before the dependency precheck; count only tables in the shared check; admit replacement writer starts; authenticate before the first-record chain check. The dependency-precheck mutation first survived. The cross-writer causal test now asserts that no engine copy is made while a dependency is missing, and it catches the mutation. The execution record lists each substitution, command and failing test. This is targeted invariant testing, not exhaustive mutation coverage.

Final gates run after restoring all mutated source: formatting, Clippy with warnings denied, the full Rust suite under normal and ignored-inclusive discovery, both independent Python fixture regenerations, optimized-Python oracle guards, and source/evidence hash verification.

## Limits

This remains test-only code with fixed trusted configuration, one document and one epoch. A merged view without a valid projection is reported, not repaired. Undecryptable records stay pending until a matching key is supplied. The sibling `Replica` (the unauthenticated Loro adoption prototype) still rejects records whose merged projection fails and keeps the first record per ID. It has no multi-writer use, so it is unchanged here; the same causal-past rule applies if it gains one. Local database tampering stays outside the model; it now also covers the committed authentication facts and engine snapshot, which have the same trust as the retained ciphertext.
