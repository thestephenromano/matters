# Fuzzing the sync parsers and receiving

[cargo-fuzz](https://github.com/rust-fuzz/cargo-fuzz) (libFuzzer) targets for every parser that reads sync input from outside the process (#36), and for what a device does with input that passes them (#45). This setup was decided on #36 on 2026-11-21.

| Target | Input | Invariants beyond "never panics" |
| --- | --- | --- |
| `record` | a content record | an accepted record re-encodes to exactly its bytes; none verifies under the fixture's key |
| `control` | a control record | an accepted control re-encodes exactly; no transition, recovery, writer claim, envelope or enrollment it carries is admitted by a fixture collection |
| `invitation` | a scanned invitation or a published offer | an accepted one re-encodes exactly |
| `typed` | typed recovery words or an invitation code | an accepted one round-trips through its own printed form |
| `checkpoint` | a checkpoint part or coverage statement (#40) | accepted ones re-encode exactly; a checkpoint assembled from a lone part re-encodes to that part |
| `relay_page` | a relay's page of a record or authority log, or its error body (#45) | a page the client accepts, against any cursor, keeps the contract: at most 256 entries ascending past the cursor, a next cursor of its generation within the high-water mark, complete exactly at the high-water mark and advancing otherwise; a relay's requested wait is capped at ten minutes |
| `relay_snapshots` | a relay's list of its newest snapshot records (#40, #45) | none beyond "never panics" |
| `relay-request` | a relay API request body (#45) | an accepted one has exactly its keys, each readable |
| `relay-cursor` | a page cursor from a query | an accepted one re-encodes exactly |
| `relay-export` | an export file given to `matters-relay import` | an accepted one encodes again to bytes that parse the same |
| `relay-hint` | a commit hint's notification payload | an accepted one prints to a payload that parses the same |
| `signed_record` | a kind, a predecessor and a plaintext, sealed and signed as the fixture's admitted writer | it re-encodes exactly, authenticates and opens to the plaintext; a changed byte stops it authenticating; an opened part assembles canonically |
| `signed_control` | a control, its message signed again by the fixture key for its kind | it re-encodes exactly; whatever the authority admits, its current manifest still has a roster, or it is frozen |
| `built_checkpoint` | a checkpoint's fields | it assembles from its own parts into itself, follows itself, and is refused under another epoch |
| `engine_import` | engine bytes from a member | every decode and import, and the projection after a merge, returns rather than panics |
| `receive` | a sequence of records (raw, or sealed as an admitted member's writer around a fuzzed plaintext or engine edit), controls and page breaks, to a joined database | receiving never fails as a store; a refusal is the only error; the rows rebuild from the engine; a local write still works |

The target bodies live in [`matters_sync::fuzzing`](../crates/matters-sync/src/fuzzing.rs); [`matters_core::fuzzing`](../crates/matters-core/src/fuzzing.rs) for `engine_import` and `receive`; [`matters_sync_client::fuzzing`](../crates/matters-sync-client/src/fuzzing.rs) for the two `relay_*` targets; and [`matters_relay::fuzzing`](../crates/matters-relay/src/fuzzing.rs) for the four `relay-*` targets, behind each crate's `fuzzing` feature. That way the fuzzer and the stable replay tests (`tests/fuzz_replay.rs` and core's `fuzz_replay_tests.rs`) run the same code.

- **`corpus/`.** Generated by `python3 -I fuzz/seed_corpus.py` from the golden vectors and known answers, and committed. The `engine_import` seeds are engine bytes, written by `cargo test -p matters-core --test fuzz_replay_tests -- --ignored write_engine_import_seeds`.
- **`regressions/`.** Holds inputs that once failed. The replay test runs both directories, and every truncation and bit flip of each seed's head, in the ordinary suite.

**CI.** The `sync parsers fuzzed` job runs [`ci/fuzz.sh`](../ci/fuzz.sh) whenever `crates/matters-sync`, `crates/matters-sync-client/src`, `crates/matters-relay`, receiving in `crates/matters-core` (`src/storage`, `src/crdt`, `src/fuzzing.rs`) or `fuzz/` changes: 60 seconds per target, on the nightly and cargo-fuzz pinned in [`ci/tool-versions`](../ci/tool-versions). A failing input is uploaded as the `fuzz-artifacts` artifact. Add it to `regressions/<target>/` along with the fix.

**Longer campaigns:** `ci/fuzz.sh --all 3600` runs each target for an hour.
